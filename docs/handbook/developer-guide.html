System scope

Documentation snapshot • 17 November 2026. Based on the current workspace, including changes awaiting a Git commit. Local tests cover PostgreSQL 18, SQL Server Express and MySQL 8.4.13. Production deployment, TLS and recovery verification varies by provider.

OneCart Commerce is a single-product commerce platform with multiple variants and configurable attribute groups. React and TypeScript provide the storefront and administration UI. ASP.NET Core 10 exposes HTTPS JSON APIs. Entity Framework Core persists catalog, Identity accounts, orders and audit events.

Customers check out as guests using cash on delivery. Customer contact records belong to orders. The application does not provide customer accounts, online payments or a marketplace catalog.

Architecture and request flow

Browser (React / TypeScript)
  → HTTPS JSON API
    → Authentication / role checks / anti-forgery
      → Catalog, checkout, order and admin services
        → EF Core StoreDbContext
          → Selected relational database

Images → LocalProductImageStorage → host filesystem
Reset mail → SMTP service → configured STARTTLS relay
Secrets and signed quotes → ASP.NET Core Data Protection

Keep business rules in services and explicit contracts. Endpoints handle transport, authorization and response mapping. Keep database behavior behind provider configuration and migrations. Reuse the existing persistence services when extending features.

Local developer setup

  1. Install .NET 10 SDK, Node.js 20.19+ or 22.12+, npm and the selected database server. Open SingleProductCommerce.sln for Visual Studio development.
  2. Run dotnet restore and npm ci. Configure database credentials in user-secrets or use the protected first-run installer with no operator connection configured.
  3. Trust the HTTPS development certificate from the same Windows account that runs the API.
  4. Start the API and storefront. Visit the health route and verify the catalog.
  5. Use /admin for administration and /install only for a fresh installation.
dotnet restore backend/OneCart.Api
dotnet dev-certs https --trust
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5175

# Separate terminal from the repository root
dotnet run --project backend/OneCart.Api

Local storefront http://127.0.0.1:5175. API https://localhost:44300. start-local.ps1 starts both with certificate and readiness checks. API output DLLs can be locked by an existing server process. Stop that project process before rebuilding its output or use a separate artifacts directory.

First-run installer

  1. Deploy the API and SPA with HTTPS, the exact frontend CORS origin, persistent Data Protection storage and a random setup token of at least 32 bytes.
  2. Leave ConnectionStrings:Store and ConnectionStrings:StoreFile unset for the full wizard. If the operator supplied a connection, setup uses the first-admin-only flow.
  3. Open /install. Enter the token, provider, database host and login, then test connectivity.
  4. Select the first SystemAdmin email/password, default language and active store currency.
  5. Installation applies migrations, saves protected configuration, creates Identity roles and the administrator, and writes an audit event.
  6. Sign in to /admin, configure and publish the product. The public API returns installation_required until database setup is ready.

Setup__InstallationFile controls the protected configuration path. DataProtection__KeyDirectory must persist across restarts and upgrades. Installation uses a process semaphore and is intended for one API instance during setup. Multi-instance installation requires deployment coordination. Preserve the existing database and setup state when diagnosing a partial installation.

Commerce business rules

  • A signed quote captures numeric unit price and currency when a customer adds a line. Client requests cannot supply trusted prices.
  • Guest checkout requires name, phone and delivery address with length limits. Phone and address correctness is the shopper’s responsibility.
  • Cash on delivery is the only confirmed payment method. New orders start Pending.
  • Placement decrements stock transactionally. Cancellation restores it once. Verify race conditions on every supported provider.
  • Current transitions are Pending to Processing or Cancelled, and Processing to Completed or Cancelled. Completed represents the delivered state used in currency eligibility.
  • One active store currency applies to variants and priced options. A SystemAdmin can change it only when all orders are Completed or Cancelled, with explicit manual repricing. Existing order snapshots retain historical amounts.
  • Old cart lines retain display values after a currency change, but checkout rejects stale-currency quotes and requests re-adding items.
  • Flash-sale start and end are stored in UTC. The admin enters local time. Sale prices apply during the configured interval. Attribute adjustments are added separately. The final unit price rounds once to the currency’s standard minor-unit precision using midpoint-away-from-zero rounding.

The temporary two-factor identity cookie uses Secure, HttpOnly and SameSite=None for the local cross-origin flow. Required MFA gates administrator functionality until enrollment is confirmed. Never expose authenticator secrets or recovery tokens in application logs. QR codes are generated in the browser from the authenticated setup response.

SMTP and account recovery

SystemAdmin configures SMTP through Accounts → SMTP and password recovery. STARTTLS is required by the sender. Gmail uses smtp.gmail.com and port 587 with a Google app password. Port 465 implicit TLS is not implemented by the current SMTP sender. Save settings before selecting Test saved settings. The test targets the signed-in administrator’s email.

AdminSmtpSettings encrypts the password using Data Protection. Blank password input preserves it only when host, port and username remain unchanged. Host configuration supplies initial settings. The reset URL must match a trusted frontend origin and /admin/reset-password. If omitted, the server derives it from the request’s allowed origin. New links carry email and token in the fragment. Successful reset changes the password, clears failed attempts and temporary lockout, and records an audit event.

Localization, UI and media

  • English, Bangla and Spanish interface labels ship with the storefront. Installation selects the default. Visitors can choose a language and keep that preference locally.
  • Administrators maintain product, variant, option and storefront translations. English provides per-field fallback.
  • Theme configuration uses constrained color and font-size inputs with preview. Arbitrary CSS entry is excluded.
  • Product images and brand logo have independent actions. JPEG, PNG and WebP up to 10 MB are current defaults.
  • Reviews are created and published by administrators. Public submission is disabled.
  • Responsive layouts cover storefront, variant rows, admin navigation and order details. Recheck small-screen overflow after UI edits.

Deployment, packaging and recovery

Docker Compose, Linux with systemd/Nginx and Windows IIS have configuration and deployment guides. docker-compose.wizard.yml starts a deployed wizard against an external database. The regular Compose stack supplies PostgreSQL and migrations. Packages contain the API, SPA, documentation and runtime API URL configuration. The host must provide DNS, HTTPS termination, exact origins and persistent storage.

  1. Build and verify packages and SHA-256 checksums. Set storefront/runtime-config.js to the actual public HTTPS API origin.
  2. Configure trusted proxy IPs only where TLS terminates at that proxy.
  3. Back up the database, local media, installation configuration, SMTP settings and Data Protection keys together.
  4. Before an upgrade, capture and test a backup. Apply migrations using one API instance and verify health plus a real application read.
  5. Restore in isolation, confirm order totals, stock, admin identity and image access, then rehearse rollback before live deployment.

The health endpoint proves process responsiveness. It does not validate every database operation or SMTP delivery. Consult deployment, PostgreSQL recovery and SQL Server recovery.

Troubleshooting and extension rules

SymptomAction
DLL copy errorsLocate the OneCart process holding the build output. Stop it or build to isolated artifacts.
API unavailableVerify https://localhost:44300/health, current logs, connection credentials and migrations.
401 at password stepUse the current password. Check temporary lockout. A successful password reset clears it.
401 at MFA stepRestart the email/password step if its temporary cookie expired. Use the current app code and automatic device time.
Invalid reset tokenRequest the newest email. Used tokens and account security changes can invalidate previous links.
SMTP failureCheck relay host, port 587, sender, app password, outbound connectivity and certificate trust.
Database column missingApply the selected provider’s migrations to the database actually configured.
Missing images after restoreRestore the media directory and matching database metadata.

When extending features, update PRODUCT_REQUIREMENTS.md for owner decisions, implement rules in services, provide a migration for every supported provider, add focused behavior coverage and keep setup documentation current.
