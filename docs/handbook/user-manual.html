Before you begin

Documentation snapshot • 17 November 2026. Based on the current workspace, including changes awaiting a Git commit. Local tests cover PostgreSQL 18, SQL Server Express and MySQL 8.4.13. Production deployment, TLS and recovery verification varies by provider.

The host operator deploys the application, configures HTTPS and gives the owner the store URL and one-time setup token. The store owner completes setup and publishes the product. All screenshots or sample values in this manual are illustrative. Use your own brand, products and business contact details.

First installation

  1. Open your store URL followed by /install.
  2. Enter the setup token supplied by your hosting operator.
  3. Choose the database provider and enter the database host, port, name, username and password. Test the connection. Default ports are PostgreSQL 5432, SQL Server 1433 when a port is required, and MySQL 3306.
  4. Enter the first SystemAdmin email, a strong password of at least 12 characters, and matching confirmation. Include uppercase, lowercase, a number and a symbol.
  5. Choose English, Bangla or Spanish as the default language, then select your store currency.
  6. Select Install store. Wait for completion, then continue to admin sign-in.
  7. Create and publish the product to make it visible to guests.

SQL Server and MySQL currently appear as experimental options. Ask your hosting operator to confirm the intended production provider. If the host already configured a database, setup displays only the first-administrator form.

Sign-in and account recovery

  1. Open /admin and enter your administrator email and password.
  2. At first sign-in with a temporary password, set your own password.
  3. If prompted for authenticator verification, enter the current six-digit code from your app.
  4. To enroll MFA, open your authenticator app, add an account by scanning the QR code, then enter its current six-digit code in OneCart.
  5. Use Sign out when you finish on a shared device.

After five failed attempts, sign-in pauses for 15 minutes and then allows retries automatically. If you forgot the password, enter your email on the sign-in page and select Forgot password? Send reset link. Open the newest email, choose a new password, and sign in again. A completed reset clears a temporary account block.

When a SystemAdmin resets MFA enrollment, the previous authenticator entry no longer works. If MFA is mandatory, scan the new QR code after password sign-in. If optional, you can enroll again from your account controls.

The left menu shows areas permitted by your assigned role. On small devices, use the menu icon to open navigation. The public-store control in the header opens the guest storefront. Only SystemAdmin creates accounts and assigns roles.

Create the product

  1. Open Catalog and expand Product information. Enter product name, slug, description and publication state.
  2. Choose the store currency during initial product setup if installation has not already set it.
  3. Add a variant with a unique SKU, display name, regular price, stock quantity and active state. Add further variants for sizes, packs or other choices.
  4. Use the Prices and Inventory sections to check every variant. Variant details, price and inventory share a save scope.
  5. Save the section. Review the stored values before publishing.
  6. Use the public store button to confirm the product and its active variants appear correctly.

Use Edit to change a saved section, Save section or Save variant data to apply it, and Cancel to discard staged changes. Save the current section before switching edit scope. Use explicit delete controls to remove child entries when allowed. Variants referenced by orders must be deactivated instead of deleted.

Attributes and options

  1. Expand Attribute groups. Add a group such as Color, Package or Gift wrap.
  2. Set whether a shopper must choose an option and whether multiple choices are allowed.
  3. Add choices, names, price adjustments and active states.
  4. Save the attribute section and check the shopper selection on the storefront.

Groups belong to the product and choices belong to a group. Add or remove as needed within editor limits. Attribute adjustments add to the selected variant amount. Combination-specific stock and compatibility rules are not a confirmed feature.

Images and brand logo

  1. Open the media section and select a product image from your computer.
  2. Enter alternative text that describes the image for accessibility. Upload it.
  3. Preview the saved picture, adjust order or alternative text, and save metadata.
  4. Delete obsolete pictures using the image’s delete action.
  5. Use the separate brand-logo controls to update the store logo.

Current accepted formats are JPEG, PNG and WebP up to 10 MB. The product can have up to eight images and one logo. Files are stored on the application host. Keep copies in the store backup. The storefront shows the gallery and thumbnails below the image area.

Storefront presentation

Open Storefront to manage the brand name, headline, About Us, benefits, product details, shipping and returns text, and the multiline How to use content. Product data can describe any suitable product category. Maintain the information you promise to shoppers.

  1. Set your brand name and compact headline for the header. Copyright uses the configured brand name.
  2. Add About Us content and product-specific benefit entries.
  3. Enter readable usage instructions in the multiline text field.
  4. Set permitted colors and font sizes using the selection controls, then check the live preview.
  5. Save and open the public store on both desktop and mobile.

The purchase reassurance labels include 100% Authentic, Fast Delivery, Easy Return and Customer Support. Verify that your store’s service policies support those messages. The application does not provide a standalone support portal or wishlist.

Flash sale and pricing

  1. Open the flash-sale settings. Enter a campaign label, percentage or fixed discount, start time and end time.
  2. Check every variant’s price and the resulting sale amount.
  3. Save, then view the public store during the active interval. The page shows current price, previous price, savings and countdown.
  4. Disable an obsolete sale when it ends or before changing currency.

The schedule uses your local time in the form and stores UTC on the server. The sale/base price and selected option adjustments are combined, then the final unit price is rounded once using the active currency’s standard decimal precision. BDT, USD, EUR and GBP use two decimal places; JPY uses none; KWD uses three. Quantity multiplies that saved rounded unit price.

Changing store currency

SystemAdmin can choose another active currency only when every order is Completed or Cancelled. Pending or Processing orders block the change.

  1. Finish or cancel open orders through the supported order workflow.
  2. Edit Product information and select the new currency.
  3. Enter fresh amounts for every variant and every previously priced option. The previous sale is disabled.
  4. Confirm that prices were entered for the new currency and save.
  5. Review the public product and configure any new promotion.

Existing orders retain their original values. Old cart lines retain their saved display amounts but must be added again before checkout in the new currency. OneCart does not perform automatic currency conversion.

Languages

The storefront supports English, Bangla and Spanish. Visitors select a language from the header. The installation default applies until a visitor chooses another language. In the catalog and storefront editors, enter translated values for product names, descriptions, variants, attribute choices and store content. Missing translated fields use their English values. Check each language in the public store after saving.

Reviews and sharing

  1. In Storefront settings, add an administrator-managed review with display name, rating, title and review text.
  2. Save as unpublished while reviewing the content. Publish it when ready.
  3. Check that the public rating summary and review section reflect published reviews.
  4. Enable sharing and WhatsApp if required, set the store’s business phone number and prefilled message, then test the controls.

Reviews are maintained by administrators. Customers do not submit reviews through a public form. WhatsApp uses the configured business contact link. Store owners are responsible for accurate review and service claims.

Guest shopping and checkout

  1. Open the public store. Select an active variant and any required attributes.
  2. Choose quantity and select Add to cart.
  3. Review selected options, saved unit price and cart total.
  4. Proceed to checkout. Enter name, phone and delivery address.
  5. Confirm the cash-on-delivery order. Save the order number displayed on screen.

Stock is reduced when the order is placed. Provide correct phone and address information so the store can deliver. The store’s administrators manage later confirmation or cancellation. Shoppers do not need a customer account.

Orders and contacts

  1. Open Orders and select an order to see its lines, customer details and saved totals.
  2. Move Pending to Processing when your store starts fulfillment.
  3. Move Processing to Completed after delivery.
  4. Cancel a Pending or Processing order when appropriate. Cancellation restores its stock once.
  5. Use customer contact search to locate order-associated names, phones and delivery addresses.

Summary totals are grouped by status and the currency saved on each order. Historical currencies remain separate. Contact records correspond to orders rather than merged customer profiles.

Accounts, MFA policy and audit

  1. As SystemAdmin, open Accounts and create a user with email, temporary password and the appropriate role.
  2. Give the temporary password to that administrator through your approved secure channel. The administrator must change it at first sign-in.
  3. Update roles as responsibilities change.
  4. Choose whether authenticator MFA is optional or required.
  5. Reset another administrator’s enrollment when their authenticator must be replaced.
  6. Use Audit to review recorded product, user, settings and order changes.

SMTP setup and testing

  1. As SystemAdmin, open Accounts → SMTP and password recovery.
  2. For Gmail enter smtp.gmail.com, STARTTLS port 587, and your full Gmail address as username and sender. Create a Google app password for the password field. For another relay, use that provider’s settings.
  3. Save settings. The saved password field remains empty afterward.
  4. Select Test saved settings. Check the signed-in administrator’s inbox and spam folder.
  5. After receipt, request a password reset for a test administrator and confirm the complete recovery flow.

If changing host, port or username, enter the corresponding password again. A blank password preserves an existing password only while those connection details stay the same. Ask the hosting operator to set the permitted storefront reset URL and outbound SMTP access. Port 465 is not supported by the current sender.

Troubleshooting

Message or symptomWhat to do
Service unavailableAsk the host operator to verify the HTTPS API and database configuration.
Email or password incorrectUse the latest password and the account’s actual email. A temporary block expires after 15 minutes.
Authenticator code rejectedUse the entry enrolled for this account and enable automatic device time. Restart sign-in if its session expired.
Invalid reset linkRequest a fresh email and open the newest link.
Reset email missingCheck spam, saved relay credentials and Test saved settings.
Variant missingCheck variant active state, product publication and saved changes.
Image missingCheck upload success and publication, then ask the operator to check media storage.
Currency selection disabledResolve Pending and Processing orders and use a SystemAdmin account.

For hosting, database or certificate issues, provide the operator with the route, approximate time and visible message. Keep passwords, app passwords, QR secrets and reset tokens private.
